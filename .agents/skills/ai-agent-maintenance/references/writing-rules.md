# 写作规则

文档、源码注释和回复使用自然具体的研发用语。先说明行为、条件和影响，再补充读者需要的技术依据。

## 用词与句式

- 以“配置加载”“转换任务”“运行结果”“会话版本”“Tauri 桌面层”等具体对象表达含义。
- succeeded / failed / cancelled 表示本次运行结束，之后仍可重新加载或运行；描述时写清结束的对象。
- “返回”“提交”“写入”“关闭”“回收”等动作分别说明，避免用一个完成标记代替多个确认边界。
- 少用无必要的否定对照、口号和自行创造的简称，直接说明实现和约束。
- 当前行为使用陈述句，未核验的外部事实明确标注；测试结果说明实际环境与执行范围。
- 正式文档和注释保留当前约定、理由与来源，删除任务编号、日期流水、进度和过期结论。

## 文档组织

首页和目录索引负责路由，用户文档解释操作，开发文档解释接口、实现边界和验证方式。长流程按主题拆分，不把来源细节和测试结果塞入共享入口。

列表用于并列对象或操作步骤，表格用于字段与平台比较。结构、通信和复杂流程优先 Mermaid，保证链接和图示能被检查。

## Agent 配置

AGENTS.md 只放高信号、常用、难从源码直接推断的规则，细节链接到模块文档和 Skills。CLAUDE.md 导入共享入口，工具专属文件只补必要差异。

Skill description 写清使用意图及近似场景边界，正文说明输入、操作与验证，较长参考放 references 并注明何时读取。frontmatter 与目录名称遵循官方规范，来源登记在[来源索引](../../../../docs/ai/source-index.md)。
