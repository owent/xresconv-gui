# 配置与转换

## 配置加载

[loader.ts](../../packages/backend/src/config/loader.ts) 实现严格 UTF-8、单根 XML、全局/条目/输出/GUI 字段合并和包含文件解析。[isolated-loader.ts](../../packages/backend/src/config/isolated-loader.ts) 使用受监督 helper，使父进程能响应取消、超时和故障。

包含路径以声明文件为基点，通过 realpath 检查重复和循环。加载期限覆盖进程启动、读取、解析与结果传输，成功后才提交新会话，失败保留已提交配置。

| 资源 | 上限 |
| --- | --- |
| 单个 XML | 64 MiB |
| 累计 XML | 128 MiB |
| 包含深度 / 文件数 | 64 / 1024 |
| XML 节点数 / 嵌套深度 | 1000000 / 100 |
| 单个脚本 / 累计脚本 | 1 MiB / 8 MiB |
| 隔离加载期限 | 30 秒 |

脚本超时缺省 30000 毫秒，合法值为 1–2147481647，非法配置回退到缺省值。解析与预算约束以源码常量为准，修改时补失败和边界测试。

## 选择和命令构造

三态选择由 `compat-service` 统一实现，后端和脚本镜像复用同一逻辑。不可选节点跳过，全选处理整个树；搜索与键盘焦点属于表现状态，不改变已选择集合。

任务集合为已选条目与有资格输出类型的组合。tag/class、各类型重命名和输出目录、全局回退、重复参数及参数顺序由配置模型和命令构造器处理。预览与运行共享构造逻辑。运行开始固定条目集合，转换前事件后构造命令，条目字段修改可影响本次命令，选择变化供后续事件和下次运行使用。

## Java 执行

Java 通过可执行文件和参数数组启动，不经过 shell。Java 选项置于 `-jar` 前；调试展示字符串不作为执行输入。

stdin 模式按 xresloader token parser 编码每条任务，处理单/双引号、ASCII 分隔空白及行分隔字符。空参数、换行或引号组合无法准确表达时，该任务回退到 argv。不能复用 Bash、PowerShell 或 Windows 命令行转义规则。

有限批次按背压写入，同时读取 stdout/stderr。写入结束关闭 stdin，等待进程退出、管道收尾及子树回收。取消停止继续派发，回收已经启动的进程。

JAR 的累计退出码不能可靠代表失败条目数量；没有逐任务确认时保留批次结果和条目结果未知状态。

### 并发控制

并发设置是会话级的 `auto` 或 1–16，默认 `auto`，不写入配置覆盖；数字保持向下取整和范围夹取。运行中不能修改。界面选择超过 6 的数字时仍需确认，选择 `auto` 直接提交。

执行前异步读取本次有效 JAR 的 `application.properties`，按 Java Properties 的转义、续行和重复键规则解析构建版本。`-Dxresloader.version` 只覆盖展示和默认数据版本，不改变并发能力判断。按主、次版本数值比较，2.24（含 2.24.0-beta）及以上将全部任务按原顺序提交给一个 JVM，并在 `--stdin` 后传入 `--parallelism auto` 或所选数字。JAR 路径或内容变化后重新读取，不依赖文件名推断版本；读取期间支持取消。

低于 2.24 或无法识别版本时，继续 round-robin 分配到多个 JVM，不传 `--parallelism`；`auto` 使用原默认值 2，数字沿用原进程数，实际进程数不超过任务数。空任务不读取 JAR、不启动 JVM。版本识别失败只回退调度方式，JAR 执行错误仍按原失败处理报告。

验证覆盖新旧版本、beta 与后续主版本、自动和数字并发、展示版本覆盖、未知版本、JAR 替换与相对路径、任务顺序、空任务、读取及执行期间取消和失败汇总；真实 JAR 冒烟通过 `--version` 和 `--help` 独立核验版本与参数支持，并核对产物和进程数。

## 日志

[log-pipeline.ts](../../packages/backend/src/service/log-pipeline.ts) 保留原始消息，按顺序经过日志钩子链，并为内存日志分配 seq。递归日志绕过钩子；在途处理过载时绕过钩子并报告数量。

内存容量缺省 10000 条，前端窗口上限 2000 条，后端分页每次最多 1000 条。超出保留窗口的日志无法通过导出恢复。

log4js 配置与 appender 在独立 sink 进程执行。配置限额 1 MiB、单条编码记录 256 KiB。合法记录先同步写入私有临时文件，再按序以最多 64 条、1 MiB 的批次发往 worker；磁盘写入向同步日志生产者施加背压，内存不随突发日志条数增长。启动时提交整批转换任务不会因超过 128 条而丢失落盘日志。临时队列大小取决于积压量，磁盘写入失败会终止 sink 并报告错误。

worker 确认处理后才回收已排空的暂存文件；关闭时先排空队列，再调用 log4js.shutdown。请求和关闭期限保持 5 秒，额外管道关闭等待有独立限额。超限记录明确报告未持久化；worker、磁盘或关闭失败会拒绝 shutdown，并在诊断中给出尚未确认记录的暂存路径。失败时保留的 pending.frames 使用 IPC 长度前缀 JSON 帧格式，可能含已经发送的记录，不自动重放；正常关闭删除临时目录。这是排队和有界收尾保证，不提供断电持久性保证。

## 扩展与回调

脚本在 worker 内重建条目、节点和共享别名，合法修改以带版本的操作回传。按钮 `data` 按按钮身份保留，选择器重建更换代际。日志镜像只读，弹窗回调绑定调用与会话，取消和重载撤销过期 token。

具体入口和代码示例见[用户脚本文档](../user/scripts.md)，接口字段见[接口文档](interfaces.md)。
