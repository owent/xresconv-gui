# 应用资源包与启动缓存

## 发行与缓存合同

发行布局包含 `app-resources.zip`、`runtime-manifest.json` 和独立的目标 Node 运行时。ZIP 保存原有 `app/` 树，包括业务入口、生产依赖、Schema 和原生模块。清单的 `resourceArchive` 记录 ZIP 路径、大小和 SHA-256，`files` 继续记录解压后的逐文件大小、摘要、来源和许可，供校验、SBOM 和模块闭包复用。

桌面窗口先显示资源准备界面，Rust 在后台执行包校验、缓存清理和解压。准备完成后才挂载业务界面、启动 guardian；各 Node 子进程和脚本模块解析以缓存中的 `app/` 为根。开发启动不生成或解压资源包。

缓存固定使用系统应用缓存目录下的 `resources/payload`，其中 `version.json` 保存应用版本和资源包摘要。应用只有一份活动资源缓存；安装目录、AppImage 文件名或临时挂载路径变化均不会产生额外的版本缓存。版本或摘要变化、完成标记缺失、文件缺失或摘要不符都触发重建。

## 更新与失败处理

1. 校验资源包摘要、ZIP 条目和清单。拒绝绝对路径、父目录跳转、重复文件、符号链接和清单外的文件。
2. 用准备锁串行化缓存操作。运行中的实例持有共享使用锁；重建需要独占使用锁。旧实例仍在运行时明确报错，由用户关闭旧实例后重试。
3. 重建前递归删除整个旧 `payload`，包括清单外的残留和只读文件，确认目录完全不存在后才创建新目录并解压。删除失败立即停止，禁止在旧目录上叠加文件。
4. 按清单逐文件解压、检查长度和 SHA-256，恢复 Unix 可执行权限。最后写入 `version.json`。失败时删除不完整缓存；进程被终止时，下次启动依据缺失的完成标记清理并重新解压。
5. 缓存复用前核验实际文件和完整目录集合。准备完成后持有共享使用锁，直至应用退出且子进程回收完成。

清理只操作应用资源缓存，不删除用户配置、日志、显示设置或安装目录中的文件。不同版本不能同时替换正在使用的缓存，需先关闭旧实例。

## 进度与验证

准备界面显示校验、清理和解压阶段。解压百分比按实际写入字节数计算，显示已完成文件数；完成标记写入后才报告就绪。发生错误时显示原因和重试按钮，业务界面保持未启动。发行程序缺失资源包或运行时清单时同样阻止业务启动。

单元测试覆盖首次解压、缓存复用、版本和摘要变化、清单外残留、只读文件、文件损坏、中断恢复、删除失败、包损坏、非法 ZIP 条目、并发实例和进度。发行测试校验 ZIP 内真实文件、原生模块与清单一致，解压后的全链测试继续覆盖子进程和动态模块加载。各平台介质和实际启动按[测试文档](testing.md)分别验收。
