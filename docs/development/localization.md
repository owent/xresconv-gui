# 多语言

## 语言选择

界面语言偏好保存为 `display-settings.json` 的 `language` 字段。缺省为 `system`，手动选择优先于系统检测；字段缺失或值不受支持时使用系统模式，后续保存其他显示设置时同步规范化该值。

桌面通过只读 Tauri 命令 `get_system_locales` 获取系统的有序语言偏好；浏览器预览使用 `navigator.languages`，监听 `languagechange`。按偏好顺序匹配语言及地区变体，均不支持或没有有效语言时使用英文。中文按 Hans/Hant 或 CN/SG 与 TW/HK/MO 区分简体和繁体。

支持英文、简体中文、繁体中文、日语、德语、法语和西班牙语。显示设置中使用各语言的本地名称，切换立即生效，不重建业务会话，也不改变选择、设置草稿或转换任务。

## 文案与渲染

`apps/desktop/src/i18n` 保存语言目录、匹配规则和共享状态。英文目录定义全部消息键；其他目录按同一键集合编写，插值使用具名占位符，例如 `{count}`，以完整句子表达动态消息。缺失或空白翻译回退对应英文。

组件通过 `useI18n()` 订阅语言，非组件调用通过 `translate()` 读取当前语言。文案以 React 文本渲染，插值不生成 HTML。根 `lang` / `dir` 和 React Aria `I18nProvider` 同步使用解析后的语言，无障碍名称、提示、内置按钮和原生文件对话框标题一并翻译。

项目条目、路径、按钮与事件名称、脚本弹窗标题和内容、Java/xresloader 及后端原始诊断保留来源文本。应用自己生成的诊断按生成时的语言记录，切换语言不改写既有日志。配置字段和协议标识保持原值。

## 扩展与验证

新增语言时提供独立目录、加入语言清单与语言匹配、更新 Rust 写入白名单，并运行类型检查及目录完整性与占位符测试。新增文案先定义英文键，再补齐其他目录；翻译按主题归类，避免在组件内拼接句子。

单元测试覆盖偏好顺序、地区与中文文字变体、无效输入、英文回退、插值安全、设置兼容和写入合并。组件和浏览器测试覆盖语言切换、无障碍标签、保留项目文本及长翻译布局。既有中文测试明确固定语言，避免依赖宿主系统。
