## 测量中修复的真实缺陷（4 项，全部 RED→GREEN）

| 缺陷 | 现象 | 修复 |
| --- | --- | --- |
| 100k 压力用例被读取预算拒绝（F01 兼容） | 旧版能加载 10.8 MB/100k 条目单文件；新 loader 单文件 8 MiB 上限直接 CONFIG_LIMIT（bigtree 测量复现） | `loader.ts` 预算 8→64 MiB 单文件、32→128 MiB 总量（与 ipc/guardian 64/128 MiB 帧预算同尺度；03 册明示预算是保护上界非功能限制）；回归：config-boundaries 新增 >8MiB 100k 条目加载用例 + 64MiB+1KB 拒绝用例 |
| 日志 sink 异步拒绝逃逸为 unhandled rejection | 只读/不可写日志文件时 `sink.append()` 的 Promise 拒绝不被 `emit()` 的同步 try/catch 捕获——可能杀死 backend 进程（EX04/R09 红线） | `log-pipeline.ts` emit 对 sink 返回值 `Promise.resolve(...).catch(() => {})` 兜底；可观测性走 onDiagnostic 通道 |
| 会话 dispose 裸 await 日志 shutdown | 日志后端不可用时 `dispose()` 整体拒绝，清理链失败 | `session.ts` dispose 按"超时不冒充成功"同款模式捕获并记 `log4js shutdown failed` 诊断；回归：sink 级契约 + 会话级 dispose 容忍两用例 |
| 日志滚动区无键盘访问（仅 WebKit axe 检出） | `scrollable-region-focusable` serious 违规，`.log-list` | `LogPanel.tsx` 列表容器补 `tabIndex={0}` |

## 工具与口径（可复现）

测量脚本与原始 JSON 保留在 `build/p6-05/`（索引见该目录 README）：

- `throughput.mjs` → `throughput.json`：ConversionSession（parallelism 2）+ 真实 JAR + 样本表格；记录每批 durationMs 与 java RSS 峰值。
- `bigtree.mjs` → `bigtree.json`：生成 10k/100k 条目 XML（50 分类），计时 parseXmlConfig/session.loadConfig/快照序列化。
- `p95-browser.mjs` → `p95-browser.json`：生产 preview + Chromium，mock 桥接与 tests/browser 同形态；页内 PointerEvent 派发→MutationObserver 判定（RAC 按压需 pointer 序列、真实 DOM 无 role="tree" 容器——jsdom 测试层与真实浏览器 DOM 差异已记入脚本注）。
- `startup.mjs` → `startup.json`：从 bootstrap 7z 解压的发行布局启动真实壳，WebView2 CDP（独立端口/用户目录），spawn→CDP 页面→树行出现；PowerShell 进程表重建进程树 RSS；每轮 taskkill 清理。
- `package-bootstrap.log`：`yarn package:windows --portable --variant=bootstrap` 完整构建日志（tauri release + 7z + SHA-256 边车）。

偏差与限制：启动为上限估计（驱动轮询粒度，与旧口径一致）；吞吐未计时拆分 JS hooks/Java 启动（本轮无 hook 负载，JVM 启动占主导已从批次 durationMs 可见）；p95 为浏览器层（mock 桥接即时返回，真实 backend RPC 往返未计入——桌面层交互 E2E 覆盖功能正确性）；内存为就绪时点采样而非峰值追踪；本机单环境数据，不外推其他平台。
