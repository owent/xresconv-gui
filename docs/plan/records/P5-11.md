## 2. 实现

- `matrix.ts`：`portableBundleTarget`（macOS→`app`、linux offline→`appimage`、安装器目标抛 `NO_PORTABLE_FORMAT`）、`portableArtifactName`（macOS `.app.zip`）、`portableArtifactNames`（验证范围精确 4 项，排序确定性）。
- `package-cli.ts`：`--portable`（要求显式单 `--variant`；格式覆盖 + macOS 分支经 `selectArtifact(bundle/macos, ".app")` + `ditto -c -k --sequesterRsrc --keepParent` 压缩；`zipMacAppBundle` 仅 darwin 宿主可达）；tauri build spawn 超时 30→45 分钟（mac 冷缓存 release 构建余量）。
- `verify-portable.ts`（+ `scripts/verify-portable.ts` 薄入口、`yarn verify:portable`）：sidecar/SHA-256 → 解包（ditto / `--appimage-extract`，均在构建 job 内执行位完好）→ 定位 `runtime-manifest.json` → schema 校验 + 身份逐字段比对（含本次 commit）→ **manifest.files 全量存在 + 大小 + SHA-256**（与 `verifyReusableLayout` 同强度，证明打包未损坏负载）→ 包内 `runtime/node --version` 原生探针（架构正确性直接证据）→ macOS 验 Info.plist 含 `LSMinimumSystemVersion`/13.5 与主二进制；Linux 验 `AppRun` 与 `usr/lib/libwebkit2gtk-4.1.so.0` 自含闭包。
- `portable-build.yml`：4 个构建 job（rust-cache 按 OS/arch 分键）+ `verify-matrix` 聚合（`verifyReleaseArtifacts` 精确集合 + 边车哈希；CI-06 语义，无 release 写权限）。Action 全 SHA 固定（复用 P5-09 已核验版本）。

### 缺陷修复：Linux 发行布局自定位与负载被改写（`guardian.rs` + Tauri 配置）

两段发现，同根因链：

1. **壳侧自定位缺陷**：壳候选此前只有"exe 同级 + `../Resources`（macOS）"，而 deb/rpm/AppImage 的 resources 在 `usr/lib/<productName>`，无候选命中——**P5-05/P5-06 的"启动冒烟"实际走的是开发态回退**（launch cwd 恰为仓库），属真实缺陷。
2. **负载落位不可用（CI 首轮 x86_64 实证 + WSL 复证）**：即使补上 `usr/lib` 候选，linuxdeploy `deployDependenciesForExistingFiles`（`appdir.cpp`）会**递归扫描 AppDir `usr/lib` 下全部 ELF**，对每个文件做依赖部署 + patchelf 改 rpath + strip——`koffi.node`（1,158,552B → 1,285,296B）与 `runtime/node`（PIE）均被改写，manifest 逐文件哈希必然失配；`NO_STRIP=1` 只免 strip 不免 patchelf，无按路径豁免。

最终修复（`/usr/share` 落位定稿，取代 P5-05 的 `/usr/lib` 布局）：

- `tauri.linux.{bootstrap,offline}.conf.json`：删除 `bundle.resources`，改经 `bundle.linux.{deb,rpm,appimage}.files` 把发行布局落位 **`/usr/share/xresconv-gui`**（linuxdeploy 扫描盲区；`copy_custom_files` 支持目录递归，deb/rpm/AppImage 三打包器共用同一语义，源码核验于 tauri-cli v2.11.5）。不落 `/opt`：AppImage 打包只把 `data/usr/` 子树拷入 AppDir（`linuxdeploy.rs` 源码约束，WSL 首测实证 `/opt` 负载整体缺失），`/usr/share` 是三格式统一、单跳自定位的唯一落位；
- `guardian.rs`：候选改探 `../share/<productName>`（exe 在 `<prefix>/usr/bin`，负载在 `<prefix>/usr/share/<productName>`；AppImage = `$APPDIR/usr/share/xresconv-gui`），Rust 回归 `release_layout_candidates_cover_linux_resource_dir` 同步更新；
- aarch64 失败另因 ARM 镜像缺 `/usr/bin/xdg-open`（`bundleXdgOpen` 默认 true 硬拷贝），CI apt 补 `xdg-utils`。

## 3.1 相邻发现：edc8b2e 遗留的 desktop E2E 超时回归（顺带修复）

本推送把用户工作树上未单独过 CI 的 `edc8b2e`（Code Review 完成）一并带入，其 `tests/desktop/{run,wdio.conf}.mjs` 重写使 ubuntu desktop E2E 首次 CI 化即三连红（bf6095c/92fa6e8 含 `--failed` 重跑复现）。排查链：

- 失败签名：`POST /session` 在 app 已拉起（AT-SPI 警告可见）、会话进行中时于 ~14.4s 被 `WebDriverError: Request timed out! Consider increasing the "connectionRetryTimeout"` 误杀；tauri-driver 报 `hyper::Error(IncompleteMessage)`。
- 排除环境漂移：绿/红两次运行同 runner 镜像（20260920.314）、同 webkit2gtk 2.52.6-0ubuntu0.24.04.1、同 webkit2gtk-driver 包版本。
- 定位：绿运行（71e7ddb）`RUNNING→PASSED` 全程 ~35s（17:08:56→17:09:31），建会话本就超过新配置的 `connectionRetryTimeout: 15_000, connectionRetryCount: 0`；该参数随 edc8b2e 的 wdio.conf 重写引入（旧 tauri-service 流程用默认 30s/3 重试）。
- 修复（e6f3893）：`connectionRetryTimeout: 120_000, connectionRetryCount: 2`。同提交 ci 双 run success（ubuntu E2E 绿；windows/macos E2E 仍为 P5-09 已登记的 continue-on-error 环境限制，非回归）。

## 3.2 增补：Linux"解压即运行"tar.gz（用户 2026-09-27 追加决策）

用户决策：Linux 需要解压直接运行的包（不要 deb/AppImage/rpm 特殊格式）；系统 WebKit 尽量复用桌面发行版附带的；tar.gz 与 AppImage 并存。落地（§合同见 [05 册](../05-packaging-release.md) §Linux"解压即运行"）：

- `portableFormats`：linux bootstrap → `tarball`（系统 WebKitGTK，≈49MB，exe 同级平铺布局=壳候选第一优先级）；linux offline → `appimage` + `tarball`（AppImage `--appimage-extract` 解包重压，复用 linuxdeploy 闭包，≈160MB）；macos → `app.zip`（不变）。portable 产物名一律不带 distro 段（发行版无关），构建基线记录在包内 `manifest.distro`。
- `package-cli.ts`：offline tarball = AppImage 解包重压（免 FUSE）；bootstrap tarball = `tauri build --no-bundle` 裸 exe + 布局平铺 + `preflight.sh`（chmod 755）。
- `verify-portable`：tar.gz 解包验证（manifest 身份/全量 SHA-256/node 探针与其它形态同强度）；bootstrap 专属检查 = 平铺布局（无 usr/ 树）+ ldd 解析到系统 `libwebkit2gtk-4.1.so.0` + preflight 就绪探针；聚合范围 4→8 项。
- 不做单包运行时自动切换：动态链接无法运行时"优先系统、缺则回退闭包"（RUNPATH 先于默认路径），两个显式包比运行时探测更稳。
- WSL 实证：三种产物 verify 全绿（各 1246 文件 SHA-256 匹配 + node v24.21.0）；bootstrap tar.gz 解压直接运行 `[guardian] ready: backend ready`（exe 同级布局在 Linux 首次实证）。CI 实证见增补后的 portable-build 运行记录。

## 4. 未验收边界

- 构建验证 ≠ 安装/运行验收：I01–I14、GUI 真实启动（WebKitGTK 集成风险、macOS Gatekeeper）归 P5-10/G5；未签名 macOS 包在他人机器会触发 Gatekeeper（无证书的既定边界）。
- manifest `verificationReport.result` 保持 `fail`；签名/公证（P5-07）、升级/卸载（P5-08）、draft release 复核未执行。
- release.yml 安装器矩阵仍缺 Windows ARM/Linux ARM/Debian/Fedora 目标；portable-only 发行策略如需落地须先修订 05 册合同。
- macOS 两变体只构建 offline（负载相同）；若未来修订使两变体产生真实差异，须恢复双变体构建。
