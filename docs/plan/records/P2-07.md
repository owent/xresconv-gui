## 目标

SC07/SC08 的内存维度：为 script worker 提供可配置资源上限并实测命中——

- V8 堆上限（`--max-old-space-size`）：堆耗尽 → V8 fatal 杀进程；
- Buffer/原生内存（堆顶管不到）→ RSS 看门狗：worker 周期自报 memoryUsage，
  guardian 超限即销毁；
- 命中后：在途 invocation 按 WORKER_EXIT 单次结算（无自动重放）、池补员、
  后续 invoke 可用、诊断可见。

速率限制与派生进程限额已由前置任务覆盖（日志风暴 5000 条实测 P2-02；派生
子进程整树回收 P2-02 process-tree + Job Object），本任务只补内存闭环。

## 实现

### worker 侧（script-host/src/worker-main.ts）

- `sendHealth` 负载新增 `memory: {rss, heapUsed, heapTotal}`（`process.memoryUsage()`）。
- 握手后启动周期自报：`setInterval` + `unref`（不拖住退出），周期取
  `XRESCONV_WORKER_HEALTH_INTERVAL_MS`（clamp 25..60000，默认 5000ms），
  shutdown 后停报。
- 已知边界（写入文件头注释）：自报是协作式的——同步死循环的 worker 无法
  上报，该情形由 invoke 超时销毁覆盖（BD-W3），与"事件循环空闲但内存慢
  增长"的场景互补。

### guardian 侧（guardian/src/script-worker.ts）

- 新选项 `workerMaxOldSpaceMb`（整数 ≥16）：spawn 时注入
  `--max-old-space-size=N`（位于 `workerNodeArgs` 之前）。
- 新选项 `memoryLimitBytes`（正整数，**BD-W11**）：RSS 看门狗上限；缺省
  不限制（只记录峰值）。
- slot 新增 `lastMemory` / `maxRssBytes`；`WorkerStat` 透出 `maxRssBytes`。
- `handleHealthReport`（BD-W7 修订：握手后的 health 帧不再纯忽略，作为
  内存样本消费）：更新样本与峰值；`rss > memoryLimitBytes` 且非 killing/
  exited → emitDiag（"exceeds memory limit ... (BD-W11)"）+ destroyWorker。
  销毁后的在途结算、弹框失效、补员全部复用既有 exit 路径（P2-01/P2-06），
  无新增分支。

## BD 新增/修订

- **BD-W11 RSS 看门狗销毁**：V8 堆顶只管 V8 堆；Buffer/external/原生内存
  由 guardian 依据 worker 周期自报的 RSS 裁决，超限即整树销毁 + 补员。
  属新增能力（旧版无任何限额），不是行为对齐项。
- **BD-W7 修订**：握手后 health 帧从"忽略"改为"消费为内存样本"（验收标准
  不变：不作为活性依据，活性仍由 invoke 路径判定）。

### SC08 边界记录（不冒充"完全沙箱"）

- V8 堆顶只覆盖 V8 堆；Buffer/原生内存只能靠 RSS 看门狗（协作式自报，
  采样粒度 = 自报周期，短时脉冲超限可能漏检）。
- 协作式自报管不了同步死循环中的内存增长（worker 卡在 runInContext 里
  无法上报）——该情形由 invoke 超时销毁兜底（BD-W3）。
- POSIX setsid 逃逸（setsid 后脱离进程组）边界见 P2-02 记录；Windows 侧
  Job Object 对未脱离 Job 的子孙进程为内核级保证。

## 测试陷阱记录（回归价值）

`Buffer.alloc(64MB)` 的零填充内存在 Windows 上**惰性提交**：只分配不触碰
RSS 不涨，看门狗永远等不到超限（实测 maxRssBytes 停在 81MB）。测试脚本必须
`fill(1)` 逐页写脏才计入 RSS。已写入 resource-limits.test.ts 注释。
