## 实施结果

### fake-converter（guardian/test/fixtures/fake-converter.mjs）

xresloader --stdin 协议的确定性 Node 模拟，`FAKE_CONV_MODE` 驱动七种模式：
echo/silent/chatty（半行拆分多 chunk 双流）/slow（20ms/行慢消费）/
early-exit（首行后 exit 7）/fail（EOF 后 exit N）/child（spawn 长生子进程
后挂起）。`FAKE_CONV_COUNT_FILE` 落盘实收任务行 JSON，供恰好一次断言。

### java-runner 测试缝

`JavaBatchOptions.spawnSpec?: {command, args, env?}`：存在时替换
`java ... -jar jarPath --stdin` 的完整 spawn 规格（生产路径不得使用，
注释已注明）。这是 fake-converter 直跑的唯一入口，行为路径（背压写/
close 收尾/整树终止）与真实 java 完全一致。

### EX02 验收映射（全部本机实测）

| EX02 要求 | 结果 | 证据 |
| --- | --- | --- |
| 各输出模式：静默进程也可完成 | 通过 | java-batch-ex02 `silent`（0 条日志、exit 0、有界完成，BD-P2 不依赖 data 驱动） |
| 各输出模式：多块日志不重复派发/不改任务数 | 通过 | `chatty`（半行拆分 + 双流交织，行缓冲拼合后恰好 3+3 条；count file 恰好 3 行不重复） |
| slow stdin | 通过 | `slow`：96×4KB（~400KB ≫ 64KB 管道缓冲）慢消费全量恰好一次、FIFO 保序 |

| 批次失败不冒充精确条目失败数 | 通过 | `fail`：4 任务 exit 3 → failedTaskCount=3（退出码语义，Main.java:407 约定） |
