## 实施结果

- `bin/worker.mjs`：plain JS 入口；先用 `node:console.Console` 把 console 全部方法重定向到 fd2（保护 fd1 帧通道），再 `await import("../src/worker-main.ts")`。Node 24 类型剥离直跑，worker-main 闭包全部 erasable-only（无 enum/namespace/参数属性）。
- `src/worker-main.ts`：fd0→FrameDecoder、fd1→writeFrame；启动即发 health（`{ok,pid,node}`，protocol_version=1、id=crypto.randomUUID()、role=script-worker）。收到 health 请求回 health（带 in_reply_to）。invoke→执行→complete（payload=ScriptResult，envelope 带 invocation_id/in_reply_to）；dialog_respond 按 payload.token（缺省回退 in_reply_to）查回调表；shutdown 等在途 invocation 完成后 exit(0)，2s 兜底强制退出；未知 kind/校验失败→fault 不崩溃。invocation 表支持多在途并发（按钮可在事件挂起期间完成）。worker 自身日志全走 fd2；uncaughtException/unhandledRejection 只记 fd2 不杀进程（脚本经注入 setTimeout 的异步回调异常不致命）。
- `src/executor.ts`：五类入口语义严格按 P0-08 §2 实现，逐字段对照见下表；差异全部为 BD-S 条目。
- 测试：16 个真实子进程端到端用例（a–p，无 mock，全部 promise-race 显式超时 ≤10s）+ 既有健康形状单测，共 17 个全绿。
- `yarn.lock`：仅追加 `@xresconv/script-host` 的 workspace 依赖条目（contracts/ipc workspace:*、@types/node 26.6.2、typescript 7.0.2），无新外部版本。仓库 `enableImmutableInstalls=true`：需先 `corepack yarn install --no-immutable` 刷新锁文件，之后 `CI=1 corepack yarn install` 通过。
- tsconfig：模板（guardian）为 NodeNext，但冻结的 `@xresconv/contracts` 根导出 `src/index.ts` 用**无扩展名**的 type re-export（`./generated/envelope` 等），NodeNext 消费者必报 TS2835（运行时无影响：type-only 语句被类型剥离整体擦除）。本包 tsconfig 因此用 `module: ESNext + moduleResolution: bundler`（同 contracts 自身配置），本包源码仍全部显式 `.ts` 相对导入。**backend（P3-01/02）从 TS 源码 import @xresconv/contracts 时会遇到同样问题**，需同样处理或统一决策。

## BD-S 差异清单（线可观测行为与旧实现的全部出入）

- BD-S1 **require 锚点**：`createRequire(invoke.context.configure_file ?? cwd)`，解析从配置文件目录开始。旧版注入渲染进程 require、锚定应用 `src/` 目录（main.js:564/2297，index.html:12-14），可 `require("electron"/"jquery")`；新版这些应用内部模块将自然失败，node:* 与配置文件邻近 node_modules 可用。
- BD-S2 **按钮 wall-clock 超时文案**：统一为 "Run event callback timeout"（旧按钮为 "timeout"，main.js:626；事件为 "Run event callback timeout"，main.js:2368）。
- BD-S3 **同步未捕获异常 → outcome "error"**：code `SCRIPT_RUNTIME_ERROR`（事件前缀 "CONV EVENT EXCEPTION"、按钮 "CONV SCRIPT EXCEPTION"、append_log 前缀 "APPEND LOG EVENT EXCEPTION" 沿用旧文案）。旧版事件/按钮把同步异常当 reject（reason=格式化堆栈），set_name 记日志后继续。新版把"脚本主动 reject"与"脚本崩溃"分开；set_name/append_log 的部分修改仍经 ops 回传（与旧活对象语义一致）。
- BD-S4 **同步 vm 超时**：while(true) 被 vm timeout 打断 → "rejected"/"Run event callback timeout"（旧版走异常 catch、reason 为格式化堆栈）。判定 `ERR_SCRIPT_EXECUTION_TIMEOUT`（注意 vm 错误跨 realm，`instanceof Error` 为 false，须结构化判 code）。
- BD-S5 **worker 外层 wall-clock 兜底**：每次 invoke 有 timeout_ms+100ms 兜底，超时 → "rejected"/reason "timeout"。旧版无此层（set_name 死循环直接卡死 GUI，main.js:1748 无 options）。限制：同步死循环期间事件循环被占，兜底定时器无法抢跑，set_name 死循环仍须 guardian 外部硬截止（runWithDeadline）杀进程——见 remaining_limits。
- BD-S6 **alert 回调调用形态**：this=undefined、无参（旧版 this=按钮 DOM、实参=[jQuery 事件]，main.js:892-916）。yes/no 抛异常时 on_close 不再调用（与旧版单 handler 顺序一致）。
- BD-S7 **注入 setTimeout/clearTimeout**（仅事件/按钮入口）：旧沙箱无计时器（ReferenceError）。新增能力使"异步 resolve"模式可用，不改变任何旧脚本可观测行为。
- BD-S8 **编译失败载体**：旧版 GUI 内 alert+日志继续加载；新版 outcome "error" code `SCRIPT_COMPILE_ERROR`，message 含 filename，由 guardian/backend 决定流程（脚本编译失败不再只是"静默缺席+日志"）。
- BD-S9 **selected_nodes/selected_items 为 JSON 快照**：无 Fancytree API（setSelected/visit/render 等调用将 TypeError）。NodeMirror/ft_node 快照降级 → P2-05。**（已于 P2-05 解决：`context.tree` 存在时 worker 重建 NodeMirror，别名/级联/ops 回流全部生效；无 tree 时仍保留本降级形态作为回退。）**
- BD-S10 **log_* 不经过 shell_color_to_html**：message=String(原始值)（Error 实例为 "Error: msg"），ANSI 颜色与 HTML 渲染是 backend/UI 职责；module 名保持 "CONV EVENT"/CONV SCRIPT 加按钮 id。
- BD-S11 **按钮 module 名用 button_id**：旧版用脚本名（main.js:529），线上 payload 只带 button_id（script-invoke.json 无脚本名字段）。
- BD-S12 **on_append_log 编排简化**：每次 invoke 独立 context；旧版同一条日志的多个 hook 共享一个 context（hook 间可见全局变量，main.js:183-204）且有递归 guard。多 hook 串行/共享/guard 属 backend 编排层职责（P3 后续）。
- BD-S13 **并发弹窗不再互相覆盖**：旧版单例 modal，后调用覆盖先调用的回调（main.js:888-891/917）；新版 token 表各自独立应答。ESC 语义（choice null→无回调）保留。
- BD-S14 **Node≥22 vm 注入 console 的处置**：`delete globalThis.console` 恢复旧沙箱 ReferenceError 语义（测试 i 证明 console.log → error outcome）。非行为差异，属平台差异的兼容措施，单列备查。
- 保持一致（非差异，登记备查）：事件/按钮注入 resolve/reject 而非 README 的 done()；set_name/事件 data 每次新建、按钮 data 按钮级持久（P0-08 附录 A.2）；按钮 global_options 数组形态保留（附录 A.3）；console/process 未注入。

## remaining_limits

- set_name 同步死循环无法在进程内打断（bug 兼容无 vm 超时；BD-S5 兜底定时器抢不过被占的事件循环）→ 依赖 guardian runWithDeadline 外部硬截止（P2-04 集成）。
- require.cache 不跨 worker 进程共享；按钮 data 只在单 worker 进程生命周期内持久 → 多 worker 调度与会话亲和是 P2-04 议题。
- selected_nodes/selected_items 为纯 JSON 快照，无 Fancytree API；ft_node 快照降级 → P2-05 NodeMirror。
- on_append_log 的多 hook 共享 context/递归 guard/append_log_context 生命周期（仅 conv_start 期间）由 backend 编排层实现（P3 后续），worker 只保证单次 invoke 语义。
- shutdown 的 2s 兜底以 setTimeout 实现；在途 invocation 若同步死循环则强制退出也须等事件循环让出（与上第一条同源）。
- 测试覆盖 win32/x64；Linux/macOS 的 stdio 帧行为由 CI 补验。
