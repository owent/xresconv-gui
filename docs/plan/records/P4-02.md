## 设计

```mermaid
flowchart LR
  shell[壳<br/>字节帧通道<br/>@xresconv/ipc 1MiB 上限] -->|kind rpc| guardian[guardian bin<br/>backend-rpc schema 校验]
  guardian -->|fork IPC kind rpc<br/>supervisor.request 有界等待| backend[backend bin<br/>BackendRpcApp]
  backend -->|kind rpc_result in_reply_to| guardian -->|kind rpc_result in_reply_to| shell
  backend -->|kind event source:backend| guardian -->|kind event 原样转发| shell
```

- 契约：`backend-rpc.json`（oneOf 判别 request/result；method 枚举即方法集，未知方法在任一校验边界即 INVALID_PARAMS）。envelope kind 枚举追加 `rpc`/`rpc_result`（P2-12 冻结规则 2：向后兼容扩展）。
- backend：`BackendRpcApp`（packages/backend/src/service/rpc-app.ts）持有 ScriptWorkerPool 与 ConversionSession（各一，会话级）；`handleRpc(method, params)` 可预期失败抛 `RpcError`，bin 映射为 `{ok:false, error:{code,message}}`，异常不漏进通道。
- guardian：`BackendSupervisor.request(payload, timeoutMs?)`（默认 30s）按 `in_reply_to` 关联 `rpc_result`；backend 未就绪/死亡/超时分别拒绝 `BACKEND_NOT_READY`/`BACKEND_DIED`/`BACKEND_TIMEOUT`；迟到或来路不明回复忽略并记诊断（SC10）；不自动重放（死亡后仅显式 restart，P2-09 合同不变）。
- 事件面（backend → guardian → 壳，kind `event`，`source:"backend"`）：`log`（管线订阅）、`state_change`（会话 onStateChange）、`dialog_request`/`dialog_invalidate`（pool P2-06 回调）、`run_end`（RunSummary）、`diagnostic`。guardian 监督事件（`source:"backend-supervisor"`）保持不变。

## 方法集与错误码

| method | params | result | 备注 |
| --- | --- | --- | --- |
| loadConfig | `{path}` | 快照 | 运行/加载中拒绝 INVALID_STATE；解析失败 CONFIG_ERROR |
| reload | — | 快照 | 未加载拒绝 INVALID_STATE；按当前 config.path 重载 |
| getSnapshot | — | `{state, runSeq, config, tree, selectedItems}` | 未加载时 config/tree 为 null |
| applyOps | `{ops}` | AppliedOpsReport | 版本闸在 SessionTreeState（P2-05），失配整批拒绝 |
| run | — | `{runSeq}` | 异步启动；进度经事件流，终态经 run_end |
| cancel | — | `{state}` | 非运行态 no-op（会话语义） |
| reset | — | `{cancelledRun}` | EX03：先取消并等实际回收再重新武装 |
| respondDialog | `{token, choice}` | `{answered}` | 迟到/未知 token 返回 `{answered:false}`（SC06 丢弃语义），非错误 |

错误码（backend-rpc schema 描述为权威清单）：backend 侧 `INVALID_PARAMS` / `UNKNOWN_METHOD`（契约枚举之外的兜底，防 schema 与实现漂移）/ `INVALID_STATE` / `CONFIG_ERROR` / `INTERNAL`；guardian 侧 `BACKEND_NOT_READY` / `BACKEND_DIED` / `BACKEND_TIMEOUT`。

## 有界上下文与测试缝

- 所有等待显式有界：supervisor.request 默认 30s（可注入）；测试用例 ≤30s；waitFor/waitUntil 带 15s 上限。
- 新测试缝（backend bin，与既有 FAKE_HANG 同节登记）：`XRESCONV_BACKEND_FAKE_HANG=1` 语义扩为"卡死的事件循环同样不应答 rpc"（既有监督用例不受影响）；`XRESCONV_BACKEND_TEST_RPC_DELAY_MS=<n>` 延迟 rpc 回复（迟到回复测试）。
- backend shutdown：有界自收尾（1500ms < guardian 2000ms 宽限）后退出；超期由 guardian 整树终止兜底（P2-09 合同）。

## 壳侧通道（Rust，main agent 集成收尾）

- `src-tauri/src/guardian.rs`：`GuardianClient`（长驻 spawn + reader 线程 demux：`in_reply_to` 命中 pending 表精确路由，其余帧经注入的 `EventSink` 转前端事件流；EOF/毒帧/死亡 → 判死、结算全部待决请求、发 `xresconv-guardian-dead`，不自动重放 SC10）；`GuardianState`（ensure/restart/shutdown，故障后 UI 显式重建）。`src-tauri/src/lib.rs`：命令 `get_backend_health` / `backend_rpc` / `restart_guardian`（均 `spawn_blocking`，不阻塞 async runtime）；`setup` 注入 emit 汇；窗口 CloseRequested → 显式 shutdown（子树自清，P2-09）。
- **加载期崩溃根因（0xc0000139 STATUS_ENTRYPOINT_NOT_FOUND）**：guardian 模块若引用 `tauri::AppHandle`/`Emitter`，unit test exe 经 `Option<AppHandle>` 的 Drop glue 保留 wry 对话框代码，导入 comctl32 **v6 专有**符号 `TaskDialogIndirect`；测试 exe 无 SxS manifest → 绑定 System32 v5.82 → 进程加载即崩。修复：guardian 模块保持 tauri-free（事件出口为注入的 `EventSink = Arc<dyn Fn(&str, Value) + Send + Sync>`），dumpbin 验证测试 exe 导入表与基线逐 DLL 一致（无 GUI DLL）。**规则：src-tauri 中被 #[cfg(test)] 测试引用的模块不得触碰 tauri/wry 运行时类型**；诊断工具留存 `build/tools/check-imports.mjs`（dumpbin 导入/导出核对）。
- **fault 尽力关联**：envelope `kind` 为封闭枚举，schema 非法帧此前只得无 `in_reply_to` 的 fault（请求方空等超时）；guardian 校验失败分支现从原始帧提取字符串 id 尽力关联（packages/guardian/bin/service.mjs）。guardian 侧 +1 用例（schema 非法 kind → 关联 fault、通道不毒化）。
- **联调修正**：壳侧 RPC payload 必须带 `type:"request"`（backend-rpc schema 判别字段）；首轮联调缺 `type` 被 guardian 边界以 INVALID_PARAMS 拒绝——schema 边界如设计工作。
- Rust 测试 5 例（真实进程、有界等待）：帧编解码 2 例；握手/health/shutdown；schema 非法 kind 关联 fault；RPC e2e（getSnapshot 空配置 → reload INVALID_STATE → loadConfig 坏参 INVALID_PARAMS → loadConfig 真实夹具 run-mirror.xml → ready 快照 → getSnapshot 选中集）。
