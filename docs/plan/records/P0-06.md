## D2 补充说明：Linux 打包策略取舍

用户询问"是否 Linux 直接完整打包更容易维护"。结论：**是，离线变体优先采用单一自含包，但 WebKitGTK 自含必须经原型验证**。

- 按发行版解析离线依赖闭包（原计划默认路径）维护成本高：每个发行版版本×架构都要独立解析、校验、干净 VM 验证，且随发行版仓库快照漂移。
- 自含包（随包携带 WebKitGTK/GTK 及传递依赖，AppImage 式或自有安装布局）把离线矩阵从"每发行版一份"收敛为"每架构一份"，长期维护更省；代价是单包体积增大（WebKitGTK 栈约百 MB 级）及集成风险：GPU/EGL 驱动、fontconfig 字体、IME（ibus/fcitx）、GStreamer 编解码、D-Bus/portal、WebKit bubblewrap 沙箱对 user namespace 的依赖。
- 决定：bootstrap 变体维持 DEB/RPM + 系统包管理器（系统内安装、复用系统库，包最小）；offline 变体优先做**自含包原型**（P5 提前原型验证，覆盖 X11/Wayland、GNOME/KDE 干净 VM）；原型证明不可行时回退到按发行版闭包，并记录取舍证据。AppImage 作为自含形态的候选实现之一评估，不再只当"额外便携产物"。
