### 归一化规则（C15 口径，2026-09-24 起）

`UnreaImportSettings.json` 是 xresloader 生成的 UE 导入辅助清单，其 `Filenames` 嵌入**输出根目录的绝对路径**（同 JAR 同参数仅 `-o` 不同即产生唯一差异，已隔离实验证实）。A/B 两路径输出根必然不同，故仅对该文件把自身输出根绝对路径替换为 `{OUT}` 再比对；其余全部产物（含 `ArrInArrCfg.json` 等业务数据）按字节严格 SHA-256。该规则窄化到单一已知文件名与单一路径前缀，不掩盖业务差异。

首轮（六格式）曾出现 3 个 hash-mismatch + 1 任务失败，逐项归因后确认**均非编码 bug**：

1. **data_ver 时间戳（jar 行为）**：xml/bin/msgpack 三个数据产物 mismatch。复现实验：同一 xml 任务两个全新 JVM 各跑一次，产物 hash 相同；同进程批次与单任务对比 diff 唯一行 `<data_ver>2.23.7.20260924021720</data_ver>` vs `...21721` —— 缺省数据版本带**秒级时间戳**，跨秒执行必然不同。处置：任务统一追加 `-a 1.0.0.0`（ps1:86 官方样例即全局 `--data-version 1.0.0.0`，本脚本因逐任务 argv 改为每条携带）。
2. **ps1:41 的 `DataSource|role` sheet 不存在（样例数据问题）**：首轮 js 任务在 A/B 两路径**一致失败**（stderr `Open data source file ... or sheet "role" failed`），失败一致性本身即差分证据。处置：js 覆盖改用 ps1:42（`-s/-m scheme_kind` + `--javascript-export amd`）；`-m k=v` 形态仍由 xml/bin/ue 四条覆盖，KeyWordRegex 类高难 token 的编码往返已由 P3-06 单测锁定。

2026-09-24 ue 补轮曾出现 2 个 hash-mismatch，归因为上述 `UnreaImportSettings.json` 内嵌绝对路径（非业务差异），按归一化规则处理后全 MATCH；业务产物 `ArrInArrCfg.json` 等隔离实验字节一致。
