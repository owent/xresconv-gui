## 设计与实现

### 1. 树虚拟化（UI03）

- **官方模式核实（不猜测）**：react-spectrum 官方 stories 的 `VirtualizedTree` = `<Virtualizer layout={ListLayout} layoutOptions={{rowHeight}}>` 包裹 Tree + 动态集合（items/render-prop + 嵌套 `<Collection>`）。本机 RAC 1.21.1 公开导出 `Virtualizer`/`ListLayout`；`childItems` 属性是 main 分支新 API，本版本用 `hasChildItems` + 嵌套 Collection（types 源核实）。
- ConversionTree 重构：Tree 改 `items` + render-prop；TreeRow 用 `hasChildItems` + `<Collection items>` 延迟子级；外包 Virtualizer（rowHeight 26 + shouldObserveItemSize）。受控 expandedKeys/搜索强扩/键盘包装（Space/焦点）全部保留，既有 15 例树测试零改动通过。
- **jsdom 窗口化验证机制**：react-stately Virtualizer 在 NODE_ENV=test 且未 mock clientWidth/Height 时渲染全部（既有测试不受影响）；mock 两属性后走真实 overscan 裁剪（源码 `getVisibleLayoutInfos` 核实）。10k/100k 用例在此模式下断言 DOM 行数有界（<200/<300）。

### 2. 传输预算提升（UI03 的硬前提）

- **实测发现**：100k 节点配置快照 JSON ≈ 37.5MB、10k ≈ 3.7MB，原 1MiB 帧上限会让大配置在传输层直接 RESPONSE_TOO_LARGE——UI03 的 10k/100k 用例根本无法端到端成立。
- 三层一致上调：`@xresconv/ipc DEFAULT_MAX_FRAME_BYTES` 1MiB → **64MiB**；Rust 壳 `MAX_FRAME_BYTES` 镜像同步；guardian 出站在途字节预算 8MiB → **128MiB**（需容纳单帧 37.5MB + 并发事件；仍有界，超限自关）。毒帧 fail-closed（分配前拒绝）语义不变。
- 测试注入：guardian 支持 `XRESCONV_MAX_FRAME_BYTES` 环境变量覆盖帧上限（仅测试用，生产缺省不变）；原"超大帧 RESPONSE_TOO_LARGE"用例改注入 1MiB 复现，新增"5000 条目（>1MiB 快照）默认预算完整过通道"正向用例；壳毒帧用例声明长度改 65MB。
- 100k 压测（backend config-perf）：完整解析（100 include 分片，含 include 图/字节预算路径）+ structuredClone + JSON 序列化，实测 parse=672ms / clone=177ms / json=97ms / 37.5MB。

### 3. 三引擎浏览器测试（UI08）

- 新增 `yarn test:browser`（根脚本）：生产构建（`vite preview`，非开发服务器）+ Playwright chromium/firefox/webkit 三引擎（浏览器经国内镜像 `PLAYWRIGHT_DOWNLOAD_HOST=npmmirror` 安装）。
- 用例（每引擎 5 例 ×3 = 15）：骨架全区域渲染且无未捕获异常（桥接降级噪声按来源分类，Firefox 对象参数 "JSHandle@object" 特性处理）；明暗主题 prefers-color-scheme 令牌切换 + color-scheme 元数据；同源资源断言（不依赖 CDN）；axe（wcag2a/2.1a/2aa）无 serious/critical 违规；窄视口无整页横向溢出。
- vite preview 显式绑 127.0.0.1（本机 localhost 仅 IPv6 解析，127.0.0.1 探测会失败——实测定位）。
