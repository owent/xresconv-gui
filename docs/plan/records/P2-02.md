## 方案调研与选型（先调研后实施，来源已入 source-index）

| 候选 | 结论 |
| --- | --- |
| Windows Job Object（koffi FFI → CreateJobObjectW / AssignProcessToJobObject / SetInformationJobObject(KILL_ON_JOB_CLOSE) / TerminateJobObject） | **主路径**。子进程默认自动加入 job 覆盖孙进程；`KILL_ON_JOB_CLOSE` 使最后一个 job 句柄关闭（含 guardian 崩溃由 OS 回收句柄）时内核终止全部关联进程——唯一覆盖 guardian 崩溃场景的方案。koffi 3.3.1：MIT、周下载约 316 万、Node-API（ABI 稳定）、win32-x64/arm64 等全目标预编译 optionalDependencies，无需 MSVC/网络 |
| taskkill /PID /T /F | **回退路径**（koffi 加载/job 创建失败时）。微软文档：/T 只终止"由它启动的子进程"，中间进程先退出则孙进程断链成孤儿；guardian 崩溃场景无人执行。只作降级，且降级被显式记录 |
| 自研 node-gyp 原生补丁 | 不采用：需 MSVC 工具链、维护成本高于引入受维护 FFI 层；计划允许"现成且经验证的系统/原生生命周期适配"优先 |
| POSIX 进程组 | linux/darwin：`detached:true` 使子进程成新组组长，`kill(-pgid, SIGTERM)`→宽限→`kill(-pgid, SIGKILL)`，ESRCH 容忍。setsid/double-fork 逃逸不设防（D4 可信脚本）；guardian 崩溃后的 POSIX 清理依赖壳层生命周期适配（P5 待办，见 remaining_limits） |

PID 重用防护：Windows 上 register 时 `OpenProcess(PROCESS_SET_QUOTA|PROCESS_TERMINATE|PROCESS_QUERY_LIMITED_INFORMATION)` 并**常驻持有句柄至 close**——持有期间内核不重用该 PID，满足"登记原生进程句柄防误杀"；kill 只作用于登记且未退出的成员。POSIX 无等价句柄，边界已记录。

## 实施结果

- `packages/guardian/src/process-tree.ts`（新增）：`createProcessScope({name?, forceBackend?})` → `ProcessScope{backend, decorateSpawnOptions, register, terminate(graceMs), dispose}`。
  - Windows：koffi 经 `createRequire` 同步惰性加载，失败降级 taskkill；`JOBOBJECT_EXTENDED_LIMIT_INFORMATION`（144B，LimitFlags@16=0x2000）经 ArrayBuffer/DataView 设置，避免结构体布局猜解。
  - `terminate`：幂等（复用首次 Promise）；job-object→TerminateJobObject 一次整树；taskkill→对每个存活根 `taskkill /T /F`；POSIX→组 TERM→宽限→组 KILL。**回收以 close 事件为准**（REAP_BUDGET_MS=2000），返回 `{reapedPids, unreapedPids}`，未确认必须上报。
  - 终止开始后才登记的子进程立即补杀，不放生；`dispose` 在仍有存活成员时先 terminate 再 CloseHandle（KILL_ON_JOB_CLOSE 兜底）。
- 接入点（全部改走 scope，删除裸 kill 链）：
  - `java-runner.ts`：可注入 `scope`（默认每批次自建）；`escalateKill` 改为 `scope.terminate(KILL_GRACE_MS)` + KILL_GRACE+REAP 兜底"cleanup unconfirmed"。Windows 上旧版 `child.kill("SIGTERM")` 本就是 TerminateProcess 硬杀，无被移除的优雅期。
  - `script-worker.ts`：每 worker slot 独立 scope；destroyWorker/shutdownWorker 超期改 `scope.terminate`；handleExit 后 `scope.dispose`；新增 `workerNodeArgs`（P2-07 资源限额入口）与 `createScope`（测试注入）选项。
  - `run-with-deadline.ts`：自建/注入 scope；**修复一个接入缺陷**：截止后 TerminateJobObject 的退出码是普通数值，exit 监听必须先判 `deadlineExpired` 再 resolve/reject，否则截止会被误报为正常退出（回归测试：deadline 用例仍抛 HardDeadlineError）。
  - `backend/service/log-sink.ts`：log4js 隔离进程纳入 scope（可注入桩）；fail 路径不再裸 SIGKILL。
- 依赖：`packages/guardian/package.json` 新增 `koffi: 3.3.1`（锁定精确版本）；`corepack yarn install` 通过，预编译二进制 0.5s 完成，无新增 peer 警告。

## 测试（全部真实子进程，无 mock；每例 ≤30s 上限）

`process-tree.test.ts` 6 例：

- terminate 回收登记子进程（close 确认，reapedPids 断言）；
- terminate 回收父→孙两级树（孙进程非登记成员，poll `process.kill(pid,0)` 求证消亡）；
- 空/已退出 scope 的 terminate 幂等无害；
- 后端诊断断言（win32 必须是 job-object，降级即缺陷）；
- **taskkill 回退路径同样回收整树**（forceBackend:"taskkill"）；
- **guardian 崩溃保护**：fixtures/scope-host.mjs 建 scope+两级树后被 SIGKILL，KILL_ON_JOB_CLOSE 由内核回收整树（root+grandchild 均消亡）。

`fault-injection.test.ts` 8 例（R02/R03/R08/R09 + P2-10）：

- `process.exit(1)` 未注入 process 全局 → SCRIPT_RUNTIME_ERROR，worker 存活（D4 语义）；
- `require("node:process").exit(1)` / `process.abort()` → 仅该 worker WORKER_EXIT，池补员后可继续服务（exitCode 透传）；
- 日志风暴 5000 条 → 控制通道无损、调用正常完成、日志全数到达；
- 卡死 worker（while(true)）被池超期终止时，其 spawn 的孙进程随树回收（R02+R08）；
- P2-10：worker 沙箱内锚定 require 实测 adm-zip round-trip、compressing gzip FileStream/UncompressStream round-trip、koffi 原生模块（Node-API）可加载。
  - 教训：compressing 2.x 的 gzip 无 `compress()` 方法，正确 API 是 `FileStream`/`UncompressStream` 管道；事件入口 resolve 值不回传（旧协议），断言只认 outcome。

**OOM 说明（诚实边界）**：曾尝试 `--max-old-space-size=64` + 字符串洪泛制造确定性 OOM，实测 V8 GC 颠簸在 15s 预算内不崩溃（时机不可界定），改用 `process.abort()` 覆盖"可控原生崩溃"；**内存/Buffer 耗尽的确定性验收推迟到 P2-07 资源限额（job/cgroup 内存上限）实现后按限额命中验证**，不再用时间不可控的 GC 颠簸冒充。

- `packages/guardian/bin/health-check.mjs`（P1 一次性探针）仍用裸 SIGKILL，未接入 scope（属 P1 占位，随长期接线一并替换）。
