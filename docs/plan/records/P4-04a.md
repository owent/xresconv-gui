## 设计

```mermaid
flowchart LR
  ui[壳 UI 表单/矩阵编辑器] -->|updateSettings fields| rpc[BackendRpcApp]
  ui -->|preview| rpc
  rpc -->|合并写入 + 白名单校验| sess[ConversionSession<br/>持有 overrides]
  sess -->|matrix 变化| tree[SessionTreeState<br/>applyMatrixEligibility]
  sess -->|run 缺省用持有 overrides| plan[buildConversionPlan]
  rpc -->|当前选择 + 持有 overrides| plan
  plan --> prev[plan 任务列表 + 输出冲突分组]
```

- **ConversionOverrides 扩展**（plan-builder.ts）：新增 `workDir?`、`xresloaderPath?`、`protoFile?: string[]`、`dataSrcDir?: string[]`、`matrix?: OutputMatrixRule[]`。语义：undefined = 用配置默认；空串/空数组 = 用户清空生效——`workDir` 空串视为未设置回退入口文件目录（BD-P5 等价，main.js:1900-1906）；`xresloaderPath` 空串 → 存在性检查失败（XRESLOADER_NOT_FOUND，对齐 BD-P4 未配置语义）；`protoFile`/`dataSrcDir` 空数组 = 不发 -f/-d（与 P3-05 冻结行为一致）。`buildConversionPlan` 消费：workDir 覆盖走同一相对解析（相对 → 按 `config.dir` join，main.js:1900-1906）；xresloaderPath 覆盖走同一存在性检查；matrix 覆盖进 `resolveEffectiveRules`（`overrides.matrix ?? config.outputMatrix`）。
- **共享判定**：矩阵模式判定（规则 >1 或唯一规则带 tags/classes，main.js:1333-1338）抽为 `isMatrixMode`（domain/selection.ts），plan-builder、tree-state 加载期、会话矩阵资格重估三方共用，不分叉。
- **ConversionSession**：持有 `overrides`；`loadConfig`/`reload` 成功时清空（表单随配置重填；解析失败保留）；`runConversion(selection?, overrides?)` 缺省用持有值，显式入参（含 `{}`）优先；`updateSettings(fields)` 合并写入并在 matrix 变化时对会话树重估矩阵资格（未加载树状态时跳过）；`getOverrides()`/`getEffectiveSettings()` 供快照。
- **有效值快照**：`resolveEffectiveSettings(config, overrides)`（plan-builder 导出）= 配置默认 ⊕ overrides 的全量表单字段 + matrix；type/rename 缺省回退链与 resolveEffectiveRules 同规则（单类型模式取矩阵首条，main.js:1397-1422；矩阵模式全局类型缺省 "bin"）；字符串无配置无覆盖回退 ""（对齐旧版表单 `.val()`）。
- **事件上下文有效值**（run.ts）：`work_dir`/`xresloader_path` 改为 overrides 优先的有效值——旧版上下文取自表单值（main.js:2254-2256），与既有 -p/-a 的 overrides 回退（main.js:1911/1945）同模式；无覆盖时与 P3-08 行为逐值一致。

## RPC 方法与结果形状（P4-02 方法集扩展）

| method | params | result | 备注 |
| --- | --- | --- | --- |
| updateSettings | `{fields}` | `{overrides, effective}` | 未加载 → INVALID_STATE；loading/运行中 → INVALID_STATE（复用 assertIdleLike）；fields 严格白名单（workDir/xresloaderPath/proto/dataVersion/outputDir/rename/type = string；protoFile/dataSrcDir = string[]；matrix = OutputMatrixRule[]），未知键/错类型 → INVALID_PARAMS |
| preview | — | `{plan:{workDir,xresloaderPath,taskCount,tasks:[{itemKey?,outputDir?,display}]}, selectionCount, conflicts:[{outputDir,rename,items}]}` | 未加载 → INVALID_STATE；当前选择（getSelectedItems）+ 持有 overrides 构建计划；PlanBuildError 按其 code 透传（如 XRESLOADER_NOT_FOUND）+ details 进 message 可读串；其他错误 → CONFIG_ERROR |

- 快照（getSnapshot/loadConfig/reload 返回）增加 `settings: {overrides, effective}`（未加载配置时 effective 为 null）；`BackendSnapshot` 类型同步。
- 输出冲突（UI04）：按 `(outputDir ?? "") + (rename ?? "")` 分组，>1 任务的组为冲突，items 为组内 item 名（去重保序）。`ConversionTask` 增补 `rename?: string` 供分组（向后兼容的字段追加）。
- protoFile/dataSrcDir 直给 string[]；旧版表单的 JSON 数组字符串编码（main.js:1298-1315）不复活。

## BD 差异

本切片无新增 BD 编号。两处与旧版形态不同但语义对齐的点：

- workDir 空串覆盖回退入口文件目录而非沿用配置 work_dir——对齐旧版"表单空 = 入口目录"（main.js:1900-1906 + BD-P5）。
- preview 的冲突分组是粗粒度启发式（同 outputDir+rename 即视为冲突，不求值 rename 模式对 item 名的映射）：旧版无输出冲突预览功能（UI04 新能力），分组规则按任务合同定义。

## 遗留

- preview 冲突分组不求值 rename 模式（如 `/(?i)\.bin$/.lua/` 对不同 item 名实际产出不冲突也会按组报告）；误报收窄属 UI04 前端联调期的可选增强。
- preview 只读当前选择快照，不冻结选择版本；选择与预览之间的一致性提示（版本冲突不覆盖）归 P4-04 前端切片（UI04）。
- updateSettings 的 matrix 资格重估只在 withRule（每条规则带 tags/classes）时产生实际禁止/恢复（applyMatrixEligibility 既有语义）；单规则无限定矩阵覆盖不解除既往禁止状态，与旧版 show_output_matrix withRule=false 不执行两分支一致。
- 事件上下文 `work_dir`/`xresloader_path` 本切片起用有效值（见"设计"）；globalOptions 仍不来自表单（配置级，overrides 不管它）。
- Linux/macOS 复验随 CI 矩阵（本机 win32/x64 实测）。
