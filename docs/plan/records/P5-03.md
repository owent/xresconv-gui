## 实现与证据

### 1. 双配置覆盖（05 册 Windows 规则 1/4）

- `tauri.windows.bootstrap.conf.json`：`webviewInstallMode.type=embedBootstrapper`（silent）。
- `tauri.windows.offline.conf.json`：`webviewInstallMode.type=offlineInstaller`（silent）。
- 公共：NSIS `installMode=both`（per-user 默认、per-machine 可选——"只在必要步骤请求权限"）、双语（简中/英）、`resources` 映射 `build/release-layout/{runtime,app,runtime-manifest.json}` → 安装根（与壳侧自定位合同一致）。两覆盖只改 WebView2 准备方式，应用负载来自同一次组装（moduleTreeHash 相同）。
- 字段形状经本机 `@tauri-apps/cli/config.schema.json` 核实（WebviewInstallMode/NsisConfig/installMode 枚举），非猜测。

### 2. 壳侧发布布局自定位（guardian.rs）

- `release_layout_paths`：exe 同级 `runtime/node(.exe)` + `app/guardian/service.mjs` 俱在才命中（半份布局不误判，单测）。
- 解析顺序：`XRESCONV_NODE`/`XRESCONV_GUARDIAN_ENTRY` env → 发布布局 → 开发态 workspace 上溯 → PATH `node`。打包产物零环境变量即可启动 guardian（P5-02 布局合同的壳侧闭环）。

### 3. WebView2 原生预检（PK02"先检查后 GUI"）

- `webview_preflight.rs`：`run()` 首行执行（任何 WebView 创建前）——EdgeUpdate Client GUID 注册表（HKLM WOW6432Node + HKCU 双位置）读 `pv`，缺失/非法/低于最低大版本（targets.json minimumWebview=120）→ win32 `MessageBoxW` 原生诊断（重跑安装器 / Evergreen 官网指引 / manifest 与日志位置）+ 退出码 2。不白屏、不依赖 WebView。
- 纯函数（版本解析/判定）单测 2 例；模块仅依赖 windows-registry/windows-sys（无 tauri/wry 类型，0xc0000139 约束不触碰）。

### 4. 打包入口（scripts/package-windows.ts）

组装（共享布局，本机 Node v24 直用，CI 换 nodejs.org 下载+SHASUMS256）→ 逐变体 `tauri build --config` → NSIS 产物按 P5-01 矩阵命名复制到 `build/dist/` + SHA-256 边车。根脚本 `yarn package:windows`。
