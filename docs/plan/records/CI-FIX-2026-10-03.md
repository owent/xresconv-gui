# 2026-10-03 Linux ARM64 release 构建修复

[记录索引](README.md) · [当前任务](../08-release-follow-up.md) · [发行约定](../05-packaging-release.md)

## 失败与根因

用户指定 [release job 111211401961](https://github.com/owent/xresconv-gui/actions/runs/37126038390/job/111211401961)，对应标签 `v3.0.0-dev.1`、提交 `9967c3822a667c8be872ff33fb4f408972b5120a`。实际 runner 为 Ubuntu 22.04.5 ARM64，镜像 `20260927.143.1`。

Rust release 编译、发行布局组装和 bootstrap tar.zst 均成功。2026-10-03 13:32:11 UTC，offline AppImage bundler 报错：

```text
xdg-open binary not found /usr/bin/xdg-open: No such file or directory (os error 2)
```

根因是 `release.yml` 的 Linux 依赖列表漏了 `xdg-utils`，而 `portable-build.yml` 已声明它。[锁定 Tauri CLI 2.11.5 的 bundler 源码](https://github.com/tauri-apps/tauri/blob/tauri-cli-v2.11.5/crates/tauri-bundler/src/bundle/linux/appimage/linuxdeploy.rs#L130) 在启用 bundle_xdg_open 时从固定路径 `/usr/bin/xdg-open` 复制文件到 AppDir；该 runner 没有预装文件。

这是构建环境依赖缺失；已有编译和 bootstrap 成功日志不代表 offline 成功，也不能以关闭 xdg-open 打包或减少 ARM64 目标替代修复。[Tauri 官方 AppImage 指引](https://v2.tauri.app/distribute/appimage/) 仍支持 Ubuntu 22.04 ARM 原生 runner，构建基线保持不变。

## 修复与回归

- release 的 Linux 安装列表加入 `xdg-utils`，与 Portable 保持一致。
- 两入口安装后执行 `test -x /usr/bin/xdg-open`，缺件在依赖阶段退出，避免编译后才失败。
- `packages/packaging/test/linux-workflows.test.ts` 检查两个 AppImage 构建入口均在打包之前声明、检查依赖。修复前 release 用例失败而 Portable 用例通过；修复后两项通过。
- 业务代码、锁文件、发行矩阵、发布权限和归档格式不变。回滚为恢复这两个工作流的差异；回滚后原 runner 缺件仍会失败。
