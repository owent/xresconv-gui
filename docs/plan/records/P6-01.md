## P6-03 泄漏循环（并入本轮实施）

新文件 `packages/backend/test/service/run-loop-stress.test.ts`：真实 ScriptWorkerPool + fake Java runner，**100 轮**加载→全选→转换，每 10 轮插入 取消（挂起 runner→converting 取消）→ reset RPC → 再次转换；共 110 次运行（90 成功+10 取消+10 重跑）。

实测（本机 Windows x64，Node 24.21.0）：runSeq 全程一致；池大小恒定（1 worker，无补员累积）；句柄三点采样恒为 7（末-首差 0）；RSS 91→103 MiB（+12 MiB，远低于 512 MiB 守卫，属正常页面缓存波动而非单调泄漏趋势）；shutdown 后全部 worker pid 回收，无孤儿。

边界：脚本 hook 均为立即 resolve 的轻量 fixture，验证的是状态机/池/句柄生命周期，不含真实 Java 负载吞吐（归 P6-05）与 GUI 层循环（desktop E2E 按平台条件执行）。
