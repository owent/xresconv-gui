## 实施结果

### guardian 侧：BackendSupervisor（backend-supervisor.ts）

- guardian 经 `child_process.fork`（可信角色通道，Plan 02 §59：execPath 固定
  为本进程 Node、json serialization、execArgv 清空）启动长驻 backend，并持有
  其整树 ProcessScope。backend 进程内自持 ScriptWorkerPool 与 per-batch Java
  scope——**树组合语义**：终止 backend 整树即覆盖其脚本 worker 与 Java 子树，
  替代逐进程登记。
- 握手：首条消息必须是 role=backend、pid 匹配、protocol_version 一致的 health
  （身份绑定实际通道 + 内容交叉校验，SC11）；伪造角色/身份错配 → 判死不 ready。
- 心跳：每 heartbeatMs 发 health ping（带 generation），heartbeatDeadlineMs
  内无匹配 in_reply_to 回复 → 失联判死。send 返回 false（通道背压）只记诊断；
  send 回调不作为送达/处理证据（SC11）。
- 判死路径（退出/失联/disconnect/协议违规/握手超时统一）：停止心跳 →
  `scope.terminate` 整树终止 → `dispose` → 发 died 事件。**不自动重放**；
  只允许显式 `restart()`（代际递增）恢复（Plan 02 §140）。
- 迟到回复：旧 generation 或未知 in_reply_to 一律忽略并记诊断（SC10）。
- shutdown：发 shutdown 帧 → 2s 宽限 → 整树终止 → dispose；幂等。

### 长驻入口

- `packages/backend/bin/service.mjs`：监督协议面（health ping/pong、shutdown、
  通道 disconnect 自行退出）。业务 RPC 属 P4；此前其他 kind 一律回 fault。
  测试缝：FAKE_HANG / TEST_DISCONNECT / TEST_BAD_ROLE / GRANDCHILD_PID_FILE。
- `packages/guardian/bin/service.mjs`：壳↔guardian 字节帧通道（1MiB 上限
  预分配前拒绝）。health 回包携带 supervisor stats；监督事件实时转发壳。
  壳通道 EOF/error/毒化 → 整树自清后退出（fail-closed，不轮询 PID）。

### backend 会话侧（session.ts）

- `reset()`（EX03 业务操作）：活动运行先取消并**等待实际回收**（run settle
  发生在 runner 终止确认之后），清运行期状态后经 loading→ready 重新武装
  （BD-O14，配置保留）；幂等、不消耗 runSeq、不杀共享池。
- `dispose()` 强化：幂等（同请求重投）；活动运行有界等待 60s，超时记
  "cleanup unconfirmed" 诊断——**不冒充清理成功**。

## 边界记录（不冒充完整保证）

- **POSIX 宿主强杀**：宿主 SIGKILL 后整树回收依赖 Windows Job Object
  KILL_ON_JOB_CLOSE；POSIX 进程组在宿主死亡时不自动回收孤儿（P2-02 已记录），
  由壳通道 EOF 自清路径（跨平台）兜住壳正常/异常退出；setsid 逃逸同 P2-02。
- guardian↔backend 是可信 fork IPC：无预分配字节上限（Plan 02 §59 明示）；
  预分配保护只属于壳↔guardian 与 guardian↔worker 字节帧通道。
- Tauri 壳侧崩溃恢复 UI（重建 guardian、会话恢复交互）属 P4；本切片交付
  的是 guardian 侧自清与事件可见性。
- backend bin 的业务 RPC（loadConfig/runConversion/树操作/日志流）在 P4
  接入；接入前非监督 kind 一律 fault。
