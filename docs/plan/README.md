## 执行与证据规则

每个任务是可独立审阅的单元：核对来源/约定 → 需求与设计（适用时）→ 失败回归 → 最小实现 → 针对性验证 → 记录/同步 → 审阅。纯文档任务运行文档检查，不制造无意义失败测试。

`todo/doing/blocked/done/deferred` 标注适用范围和实际原因。已完成阶段不重置为 todo；新增代码/运行时/介质不能继承另一提交的通过。记录字段：

```text
task_id / status / owner
source_commit / dirty_tree_digest / input_versions
changed_files / linked_requirements / linked_test_cases
commands / cwd / os_arch / case_count / exit_codes
artifact_digests / evidence_paths / remaining_limits / rollback_point
```

未实现的命令/测试目录不当作当前能力；约定不可实现先修订并说明影响，不删测试、放宽 peer、减平台或丢脚本能力换取通过。代码/数据迁移、发布通道等行为变化须有可审阅约定；本仓库未采用 OpenSpec/Superpowers。

## 必须保留的行为差异

下表为已定差异分类，具体旧观察/新断言见 [P0-07](records/P0-07.md)、[P0-08](records/P0-08.md)、[P2-11](records/P2-11.md) 与 [P3-06](records/P3-06.md)。它不表示任意平台已验收。

| 编号 | 变更 | 保留能力与约束 |
| --- | --- | --- |
| BD-01 | VM 内执行改为独立进程及外部截止 | JS/Node 公开接口保留；超时使对应 worker 会话失效，主流程收尾 |
| BD-02 | 日志 hook 改为有序异步处理 | 修改顺序/递归保护/原始日志可查，检查模块缓存差异 |
| BD-03 | Java 日志块不再作为调度确认 | 保留转换/并发，只展示可证明的批次结果 |
| BD-04 | 富文本/链接清洗 | 强调/颜色/安全链接保留，不执行脚本、事件属性或危险 URL |
| BD-05 | 完整候选配置提交 | include/覆盖/格式保留，失败不留下半份配置 |
| BD-06 | 超时/信号/重复完成统一收尾 | before/after 顺序保留；故障不当成功或重复计数 |
| BD-07 | 严格 XML、脚本文本修正 | 实体/CDATA/路径/include 保留；不复制旧 HTML 容错、二次转义或 script raw-text 缺陷，错误可定位 |

额外对象突变/include/cache 差异必须链接复现与迁移说明；要求用户改变脚本或放弃平台时呈现具体影响，不推断同意。
