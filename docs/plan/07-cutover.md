# 07 正式切换、回退与交接

[执行索引](README.md) · [上一册](06-testing-acceptance.md) · [主计划](../../Plan.md)

对应 P7。以下操作只在 G6 通过后实施；当前仅设计，不删除代码、不变更发布流程、不创建 release。

## 切换前核对

- D1–D6 有决定、证据和适用范围，不能以“跨平台”替代具体 OS/版本/架构清单；Rust 范围只限必要 Tauri 构建/胶水。
- F01–F12 和全部必需测试项已通过；真实脚本兼容不能只靠示例脚本自测。
- 引导/离线两变体齐全，macOS 系统运行时特例写入下载页与安装说明。
- UI、宿主、guardian、Node/模块、原生插件、安装器的 hash 与验收报告一致。
- 体积目标、离线完整性和主流程隔离分别验收，不互相抵消失败。

## 可回退的切换步骤

1. 固定候选代码/锁文件/运行时 manifest，停止在发行构建内解析 latest；冻结后依赖安全更新需重跑相关 gate。
2. 在新架构已可单独运行的条件下，记录旧入口与对应可用发行版本，确认用户配置/XML/选择器仍可由旧版读取。
3. 清点新旧路径引用、package scripts、prepare、图标/LFS、工作流及用户文档，再删除旧实现。
4. 移除旧实现后重跑受影响构建、生产包扫描、真实桌面启动和安装冒烟；不能拿删除前测试完全代替。
5. 组装一个完整 draft release，核对最终产物清单与测试证据；正式发布遵循项目发行流程。
6. 发布后按错误报告使用旧稳定发行回退；不得以覆盖同版本包的方式替换损坏产物。

切换提交和回退记录只包含本次重构内容，不包含用户先前的资源迁移/规则维护改动。实际创建提交、发行或部署只在对应实施任务获得授权时执行。

## 用户数据与回退

XML、选择器 JSON、Java/JAR 和转换输出继续由用户控制，新版加载不能自动改写这些文件。新增 UI 偏好/缓存使用版本化 app-data 子目录，与旧版配置分开；不把用户业务文件迁移进应用安装目录。

若发现确需写配置迁移：先确定字段合同，实施独立可重跑迁移、有备份和完整性校验，并提供旧版可读性说明。当前计划不包含未经确认的配置格式升级。

回退分两层：代码回退用于开发验证，用户回退使用保留的旧稳定安装包。已执行脚本/Java 写入的数据不能由卸载或回退自动撤销；报告哪些输出需要用户核验。安装卸载不删除共享 WebView/系统包，不强制降级安全更新。

## 文档和维护交接

| 文件/主题 | 要更新的内容 |
| --- | --- |
| README | 安装变体、支持系统、Java/Node/WebView 边界、CLI、开发/打包入口 |
| 脚本 API | 五入口准确字段、require 锚点、data/cache 生命周期、节点方法、回调、超时和隔离限制 |
| CHANGELOG / 迁移说明 | 架构变化、已修复问题、BD 差异、最低系统与平台调整、回退办法 |
| 安装/离线说明 | 每目标产物、缺 runtime 的行为、权限/重启/离线失败恢复 |
| 开发/故障排查 | Node/TypeScript 业务工具链与独立测试、Tauri 必需 Rust 构建、guardian、符号文件、真实桌面测试、调试端口约束 |
| AGENTS/CLAUDE/来源索引 | 当前实际技术栈、已存在命令、测试和不可猜测的边界；保留用户已有规则 |
| 示例配置/选择器 | 与真实脚本 API 一致，修正文档 `done()` 与 resolve/reject 的分歧 |
| Plan 与分册 | 逐任务填写证据；只勾选达到出口的任务，未决问题仍保留 |

不把规划中的命令提前写成“当前可运行”。CLI 调试功能保留，但正式包不能常开开发服务器、Node inspector、测试 WebDriver 或任意 Tauri 执行端口。
