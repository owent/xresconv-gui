# 变更工作流

## 设计与实现

先阅读 [AGENTS.md](../../AGENTS.md)、模块文档和相关源码，核对运行时、协议、依赖版本和外部官方资料。当前实现约定见[开发文档](../development/README.md)，来源登记在[来源索引](source-index.md)。

小型文案、注释和格式改动走最短可验证路径。缺陷修复先定位根因，增加能复现问题的回归测试，再做最小修复。新功能、行为变更、公开接口、数据模型、安全和部署变更先写可审阅的需求与设计合同，说明输入、行为、边界、失败处理及验证方式；已有明确授权时据此实施。

设计合同放在对应模块文档或 issue 中，实施后更新为当前约定。文档只保留现行内容，避免把任务进度、阶段编号和执行记录写入长期文档与源码注释。

验证按变更边界选择类型、lint、单元、契约、浏览器、桌面和介质检查。必须区分环境限制与产品失败，并同步维护文档入口、来源、测试和相关配置。

## Agent 配置

根 `AGENTS.md` 是共享入口，Skills 使用 `.agents/skills`，工具层只补充确有必要的差异。修改这些文件时使用 [ai-agent-maintenance Skill](../../.agents/skills/ai-agent-maintenance/SKILL.md)，先核对目标工具当前官方文档。用户授权和 harness 实际能力决定可执行操作，不能假定工具或插件已经安装。

本仓库没有采用 OpenSpec 或 Superpowers。需要引入时先评估其官方规范与仓库收益，再在明确授权下安装和维护，不能宣称已经使用。

## 外部系统与 MCP

本仓库没有项目级 MCP 接入。新增连接前核对 [MCP 官方规范和安全建议](https://modelcontextprotocol.io/docs/tutorials/security/security_best_practices)，明确数据范围、权限、认证、日志及授权方式。

密钥只在本地配置或受控密钥系统保存，不进入仓库、日志或模型上下文。优先使用只读与最小权限接口，工具输出作为外部数据处理。发布、删除、发送消息等动作遵守用户授权，自动化失败保持可追溯错误并按权限范围回收自身资源。
