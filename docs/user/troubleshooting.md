# 故障排查

## 界面语言

系统语言没有对应翻译时，界面使用英文。在“Display settings / 显示设置”的“Language / 语言”中选择需要的语言，也可恢复“System / 跟随系统”。语言偏好保存于应用程序旁的 `display-settings.json`；无法保存时检查该目录的写入权限。

项目定义的名称、脚本内容和转换器诊断保留原文，语言设置只改变应用提供的界面和提示。

## 应用无法启动

确认系统与 CPU 架构匹配、归档完整解压、资源目录未移动。Windows bootstrap 缺 WebView2 时运行包内安装器，offline 检查 Fixed Version 目录。Linux 通过启动入口查看预检输出，补齐 WebKitGTK 依赖。macOS 检查系统版本和应用安全提示。

不要只复制主程序到其他目录，Node.js、资源、模块和清单都属于应用布局。

## 配置加载失败

查看文件路径、UTF-8/XML 错误、包含循环、读取限额及脚本大小。包含路径基于声明文件，工具与数据路径按工作目录处理。失败保留会话，修正后重载。

## 找不到 Java 或 JAR

在启动应用的环境执行 `java -version`，检查与 JAR 的兼容性、JAR 路径、工作目录和权限。环境修改后重启应用。

## 转换失败或没有输出

检查预览、条目选择、tag/class 条件、表格、协议、重命名和输出目录。输出冲突提示需人工核对，继续查看 Java stdout/stderr 和实际文件。

批次退出码不提供可靠的逐条失败数量，应用不会推算未确认条目的成功状态。取消时可能已有部分文件写入，按项目需要处理后再运行。

## 脚本挂起或报错

检查事件和按钮是否调用 `resolve()` / `reject()`、模块是否能解析、是否使用未提供的 DOM、jQuery、Electron 或树接口。死循环、异常、退出和超时触发 worker 回收，查看诊断后重载配置。

脚本弹窗由确认和拒绝回调决定动作。LocalFonts 属于字体设置，Windows 桌面应用允许当前应用来源，读取失败仍可手动填写字体。

## 日志不完整或文件未写入

内存窗口淘汰旧日志，筛选影响复制和导出范围。完整持久化请配置 log4js 并确保目录可写。扩展超时、退出或队列溢出会明确记录，界面日志不代表文件已落盘。

## 反馈问题

在[问题列表](https://github.com/xresloader/xresconv-gui/issues)提供版本、系统与架构、变体、操作和日志。配置缩减为最小复现，去除密钥、账号和敏感信息。
